Render

Der Dienst läuft auf Ihrem Rechner, die Datenbank liegt bei Supabase, der Code auf GitHub – und niemand außer Ihnen kann die API aufrufen. Dieses Lab bringt den Dienst ins Netz, ohne dass jemand einen Server pflegt: Render baut aus dem Repository, startet den Prozess und gibt ihm eine Adresse. Die eigentliche Lernfrage sind drei Einstellungen, an denen fast jeder erste Deploy scheitert – und das Protokoll, das genau sagt, welche. The service runs on your machine, the database sits on Supabase, the code on GitHub – and nobody but you can call the interface. This lab brings the service online without anybody maintaining a server: Render builds from the repository, starts the process and gives it an address. The actual learning question is three settings on which almost every first deploy fails – and the log that says exactly which.

Das Problem, das es löstThe problem it solves

„Läuft bei mir“ war in Lab 07 das Problem der Umgebung; hier ist es das Problem der Erreichbarkeit. Ein Dienst, der auf 127.0.0.1:8000 antwortet, hilft dem Team, dem Dashboard in Lab 12 und der Betreiberin von Velo City nicht – sie müssen ihn aufrufen können, auch wenn Ihr Laptop zugeklappt ist. Der klassische Weg wäre ein eigener Server: Betriebssystem einrichten, Python installieren, Prozess überwachen, Zertifikat erneuern, Updates einspielen. Für ein Kursprojekt ist das der falsche Aufwand, und für viele Analytics-Projekte im Betrieb auch. “Works on my machine” was the environment problem in lab 07; here it is the reachability problem. A service answering on 127.0.0.1:8000 helps neither the team, nor the dashboard in lab 12, nor the operator of Velo City – they have to be able to call it even when your laptop is closed. The classic route would be a server of your own: set up the operating system, install Python, supervise the process, renew the certificate, apply updates. For a course project that is the wrong effort, and for many analytics projects in operation as well.

Deploy

Ein Deploy ist Build plus Start: Render klont das Repository, führt den Build Command aus, startet den Start Command und prüft, ob ein Port offen ist. Jeder Push auf den verbundenen Branch löst einen neuen Deploy aus; der alte Prozess läuft weiter, bis der neue antwortet. A deploy is build plus start: Render clones the repository, runs the build command, starts the start command and checks whether a port is open. Every push to the linked branch triggers a new deploy; the old process keeps running until the new one answers.

What gets deployed is velocity-api: a FastAPI service that reads the Velo City data from the Supabase database and answers in JSON – /stationen, /fahrten?limit=20, /kennzahlen (rides and revenue per bike type, the same query as W08-02) and / as a status. Die drei RegelnThe three rules

  1. An 0.0.0.0 binden. Der Prozess läuft in einem Container; Render erreicht ihn von außen. Ein Server, der nur auf 127.0.0.1 hört, ist innerhalb des Containers erreichbar und sonst nirgends – Render meldet dann „No open ports detected“. Bind to 0.0.0.0. The process runs in a container; Render reaches it from outside. A server listening only on 127.0.0.1 is reachable inside the container and nowhere else – Render then reports “No open ports detected”.
  2. Den Port aus PORT lesen. Render setzt die Variable (Standard 10000) und erwartet den Dienst genau dort. Einen anderen offenen Port findet Render meist auch – aber mit Warnung, und ohne Garantie. Read the port from PORT. Render sets the variable (default 10000) and expects the service exactly there. Render usually finds a different open port as well – but with a warning, and without guarantee.
  3. Geheimnisse aus der Umgebung. Der Connection String kommt aus os.environ, lokal aus .env, bei Render aus Environment Variables. Die .env-Datei liegt nicht im Repository (Lab 02) – Render kennt sie nicht, und das ist richtig so. Secrets from the environment. The connection string comes from os.environ, locally from .env, on Render from environment variables. The .env file is not in the repository (lab 02) – Render does not know it, and that is as it should be.

Die Python-Version festnagelnPin the Python version

Ohne Angabe nimmt Render für Services, die seit dem 11.02.2026 angelegt wurden, Python 3.14.x (Stand 09/2026). Das ist neuer als das, was viele Pakete fertig unterstützen – ein Build, der lokal mit 3.13 lief, scheitert dann mitten im pip install an einem Paket, das übersetzt werden müsste. Zwei Wege: Environment Variable PYTHON_VERSION mit vollständiger Nummer (3.13.5) oder eine Datei .python-version im Root Directory (3.13 genügt). Die Variable hat Vorrang. Without a setting, Render uses Python 3.14.x for services created since 11 February 2026 (as of 09/2026). That is newer than what many packages support ready-made – a build that ran locally on 3.13 then fails in the middle of pip install on a package that would have to be compiled. Two routes: environment variable PYTHON_VERSION with the full number (3.13.5) or a file .python-version in the root directory (3.13 suffices). The variable takes precedence.

Blueprint und DockerBlueprint and Docker

Wer das Formular einmal ausgefüllt hat, will es beim zweiten Mal nicht wieder tun – und will vor allem nachlesen können, was eingestellt ist. Dafür gibt es den Blueprint: eine Datei render.yaml im Wurzelverzeichnis des Repositorys, die Dienste, Pläne, Regionen und Environment Variables beschreibt. + New → Blueprint liest sie ein und legt alles an; ein späterer Push, der die Datei ändert, passt die Dienste an (Auto Sync) – und löscht dabei nie eine bestehende Ressource. Whoever has filled in the form once does not want to do it again the second time – and above all wants to be able to read what is set. That is what the blueprint is for: a file render.yaml in the repository's root describing services, plans, regions and environment variables. + New → Blueprint reads it in and creates everything; a later push changing the file adjusts the services (Auto Sync) – and never deletes an existing resource while doing so.

StolpersteineStumbling blocks

Region

Die Voreinstellung ist Oregon, und die Region eines bestehenden Service oder einer Datenbank lässt sich nicht ändern. Wer es beim Anlegen übersieht, legt neu an – bei einer Datenbank mit pg_dump und pg_restore dazwischen. Dienst und Datenbank gehören in dieselbe Region, auch weil das Private Network nur innerhalb einer Region funktioniert. The default is Oregon, and an existing service's or database's region cannot be changed. Whoever overlooks it at creation recreates – for a database with pg_dump and pg_restore in between. Service and database belong in the same region, also because the private network works only within one region.

SQLite

Die Datei aus Lab 06 neben main.py funktioniert – bis zum nächsten Redeploy, Neustart oder Spin-down. Dann ist sie weg; Render nennt „local SQLite databases“ ausdrücklich. Das Dateisystem des Free Web Service ist flüchtig wie ein Container ohne Volume (Lab 07). Daten, die bleiben sollen, gehören in eine Datenbank außerhalb (Lab 08). The file from lab 06 beside main.py works – until the next redeploy, restart or spin-down. Then it is gone; Render explicitly names “local SQLite databases”. The free web service's file system is ephemeral like a container without a volume (lab 07). Data that should stay belongs in a database outside (lab 08).

Uptime-Pinger

Ein Dienst, der den eigenen Free Web Service alle fünf Minuten aufruft, verhindert den Spin-down – und verbraucht damit die 750 Stunden, hält einen zweiten Free-Dienst vom Laufen ab und unterläuft den Sinn des Free-Plans, den Render ausdrücklich nicht für Produktion vorsieht. Wer keine Wartezeit will, nimmt 0.5c-512mb für 7 $/Monat. A service that calls your own free web service every five minutes prevents the spin-down – and thereby burns the 750 hours, keeps a second free service from running and defeats the point of the free plan, which Render explicitly does not intend for production. Whoever wants no waiting takes 0.5c-512mb for $7/month.

Free Postgres · 30 Tagedays

Die Frist läuft ab dem Tag der Anlage, nicht ab der letzten Nutzung. Nach 30 Tagen ist die Datenbank unzugänglich, nach weiteren 14 Tagen gelöscht – Render schickt vorher E-Mails. Wer sie trotzdem nutzt: vor Ablauf pg_dump, und den Termin in den Kalender. Im Kurs: Supabase. The period runs from the day of creation, not from last use. After 30 days the database is inaccessible, after another 14 days deleted – Render sends emails beforehand. Whoever uses it anyway: pg_dump before expiry, and the date in the calendar. In the course: Supabase.

Root Directory

Liegt der Dienst in api/, gehört api ins Feld Root Directory – nicht api/ in die Befehle. Render: „Files outside your service's root directory are not available to the service at build time or at runtime.“ Der Umweg pip install -r api/requirements.txt baut zwar, aber jeder relative Pfad im Code zeigt danach ins Leere. If the service lives in api/, api belongs in the Root Directory field – not api/ in the commands. Render: “Files outside your service's root directory are not available to the service at build time or at runtime.” The workaround pip install -r api/requirements.txt does build, but every relative path in the code then points at nothing.

Python 3.14

Der Default seit 11.02.2026. Lokal läuft 3.12 oder 3.13, bei Render 3.14 – und pip install scheitert an einem Paket ohne Wheels für 3.14 mit einer Meldung, die nach allem aussieht, nur nicht nach einer Versionsfrage. Immer pinnen: PYTHON_VERSION vollständig oder .python-version. Dasselbe Prinzip wie der Tag statt latest in Lab 07. The default since 11 February 2026. Locally 3.12 or 3.13 runs, on Render 3.14 – and pip install fails on a package without wheels for 3.14 with a message that looks like anything but a version question. Always pin: PYTHON_VERSION in full or .python-version. The same principle as the tag instead of latest in lab 07.

Dann liegt das Datenbankpasswort auf GitHub, in jedem Klon und im Build-Protokoll. Die Regel aus Lab 02, Lab 04, Lab 07 und Lab 08 gilt hier unverändert: Geheimnisse in die Umgebung, nie in eine Datei, die weitergegeben wird. The rule from labs 02, 04, 07 and 08 applies unchanged here: secrets into the environment, never into a file that gets passed on.
