Git und GitHub Git and GitHub

Jedes Analytics-Projekt erzeugt Stände: die Fassung, die gerechnet hat, die Fassung mit dem anderen Filter, die Fassung von vor dem Umbau. Ohne Werkzeug entstehen daraus Dateinamen wie analyse_final_v3_wirklich_final.ipynb, und niemand weiß mehr, welcher Stand die Zahlen im Bericht erzeugt hat. Git löst das – zum Preis von etwa acht Befehlen und einem Denkmodell mit drei Bereichen. Dieses Lab führt beides ein und behandelt zusätzlich die zwei Dinge, die auf keinen Fall in ein Repository gehören. Every analytics project produces states: the version that computed, the version with the other filter, the version from before the rebuild. Without a tool this yields file names like analysis_final_v3_really_final.ipynb, and nobody knows any more which state produced the figures in the report. Git solves that – at the price of about eight commands and a mental model with three areas. This lab introduces both and additionally covers the two things that must never enter a repository.

Warum nicht v3_finalWhy not v3_final

Die Vorlesung verlangt von einem Untersuchungsdesign, dass es nachvollziehbar, transparent und reproduzierbar ist. Für das Ergebnis einer Auswertung heißt das: Zu jeder Zahl in einem Bericht muss sich der Stand angeben lassen, der sie erzeugt hat. Genau das leistet eine Versionsverwaltung – nicht als Zugabe für Programmierende, sondern als Voraussetzung dafür, dass die Aussage überhaupt überprüfbar ist. The lecture demands of a study design that it be traceable, transparent and reproducible. For the result of an analysis that means: for every figure in a report, the state that produced it must be nameable. That is exactly what version control provides – not as an extra for programmers but as the precondition for the claim being checkable at all.

Was ein Commit ist – und was er nicht istWhat a commit is – and what it is not

Ein Commit ist eine Momentaufnahme des gesamten Projekts, versehen mit einer Nachricht, einem Urheber, einem Zeitstempel und einer Kennung wie a3f9c21. Er ist unveränderlich. Er ist keine Sicherung: Eine Sicherung schützt vor Verlust, ein Commit hält eine Entscheidung fest. Die Nachricht ist deshalb kein Formalismus – sie ist die einzige Stelle, an der steht, warum etwas geändert wurde. Der Unterschied selbst zeigt nur, was. A commit is a snapshot of the whole project, carrying a message, an author, a timestamp and an identifier such as a3f9c21. It is immutable. It is not a backup: a backup protects against loss, a commit records a decision. The message is therefore not a formality – it is the only place that says why something was changed. The diff itself only shows what.

Git funktioniert vollständig ohne GitHub. GitHub ohne Git nicht. Das ist mehr als eine Begriffsklärung: Es heißt, dass Sie den ganzen Ablauf lokal üben können und dass ein Ausfall des Webdienstes Ihre Geschichte nicht berührt. Pull Request ist keine Git-Funktion, sondern eine Erfindung von GitHub – ein Antrag, einen Zweig in einen anderen zu überführen, samt Ort für Durchsicht und Kommentare. Git works entirely without GitHub. GitHub does not work without Git. That is more than terminology: it means you can practise the whole cycle locally and that an outage of the web service does not touch your history. A pull request is not a Git function but an invention of GitHub – a request to move one branch into another, together with a place for review and comments.

Die drei Bereiche – das Modell, an dem alles hängtThe three areas – the model everything hangs on

Arbeitsverzeichnis ──git add──▶ Staging (Index) ──git commit──▶ Repository Ihre Dateien, Was in den Die unveränderliche wie sie gerade sind nächsten Commit soll Geschichte │ git push ▼ GitHub

Der mittlere Bereich verwirrt am Anfang und ist der eigentliche Gewinn: Sie entscheiden je Datei, was in den nächsten Commit gehört. Drei Änderungen an drei Dateien können so zu drei getrennten Commits mit drei getrennten Begründungen werden, statt zu einem Sammelcommit „Update“. Wer git add . gewohnheitsmäßig tippt, gibt diesen Gewinn auf – und committet irgendwann eine 200-MB-Datei mit. The middle area confuses at first and is the actual gain: you decide per file what belongs in the next commit. Three changes to three files can thus become three separate commits with three separate justifications, instead of one catch-all commit “Update”. Whoever types git add . out of habit gives up that gain – and eventually commits a 200 MB file along with it.

Der GrundablaufThe basic cycle

Fünf Befehle, die neunzig Prozent der Arbeit ausmachen. Der wichtigste davon ist der, der nichts verändert. Five commands that make up ninety percent of the work. The most important of them is the one that changes nothing.

Wie eine Commit-Nachricht aussiehtWhat a commit message looks like

Im Imperativ, mit Gegenstand, ohne Punkt: Ausreisserbehandlung in Preisspalte ergaenzt. Nicht: update, fix, asdf, Änderungen. Die Probe: Ergänzt die Nachricht den Satz „Dieser Commit …“ sinnvoll? Und liest man sie in sechs Wochen und weiß, warum? In einer Analytics-Arbeit ist die Commit-Geschichte oft der einzige Ort, an dem eine methodische Entscheidung begründet wurde – behandeln Sie sie entsprechend. In the imperative, with an object, without a full stop: Add outlier handling to price column. Not: update, fix, asdf, changes. The test: does the message sensibly complete the sentence “This commit …”? And will you read it in six weeks and know why? In an analytics project the commit history is often the only place a methodological decision was justified – treat it accordingly.

Zweige und ZusammenführenBranches and merging

Ein Zweig ist ein benannter Zeiger auf einen Commit – nichts weiter. Genau deshalb ist er billig: Ein neuer Zweig kopiert keine Dateien, er setzt eine Marke. Für Analytics ist das die Antwort auf die häufigste Frage im Projekt: „Was wäre, wenn wir die Ausreißer anders behandeln?“ Man probiert es auf einem Zweig aus und behält den bisherigen Stand unberührt. A branch is a named pointer to a commit – nothing more. That is exactly why it is cheap: a new branch copies no files, it sets a marker. For analytics it is the answer to the most common question in a project: “what if we treat the outliers differently?” You try it on a branch and keep the previous state untouched.

Konflikte lesen, nicht fürchtenRead conflicts, do not fear them

Ein Merge-Konflikt entsteht, wenn zwei Zweige dieselbe Zeile geändert haben. Git schreibt dann beide Fassungen in die Datei und markiert sie: A merge conflict arises when two branches changed the same line. Git then writes both versions into the file and marks them:

<<<<<<< HEAD schwelle = 0.95 ======= schwelle = 0.99 >>>>>>> experiment

Das ist keine Fehlermeldung, sondern eine Frage: Welche der beiden Fassungen soll gelten – oder eine dritte? Sie entscheiden, entfernen die Markierungen samt der verworfenen Fassung, und dann git add und git commit. Bei einer .py-Datei ist das eine Minute Arbeit. Bei einem Notebook ist es etwas anderes – dazu der nächste Abschnitt. This is not an error message but a question: which of the two versions should hold – or a third? You decide, remove the markers along with the discarded version, and then git add and git commit. In a .py file that is a minute's work. In a notebook it is something else – see the next section.

In der Zusammenarbeit kommt zwischen Zweig und Zusammenführung der Pull Request: Sie schieben Ihren Zweig nach GitHub, beantragen die Überführung, und jemand liest den Unterschied, bevor er in den Hauptzweig geht. In einer Gruppenarbeit ist das die Stelle, an der die Arbeitsteilung tatsächlich sichtbar wird – und an der ein Fehler auffällt, bevor er im Bericht steht. Ein Issue ist der zugehörige Notizzettel für offene Punkte; Closes #12 in einer Commit-Nachricht schließt ihn automatisch. In collaboration, the pull request comes between branch and merge: you push your branch to GitHub, request the transfer, and somebody reads the diff before it goes into the main branch. In group work that is where the division of labour actually becomes visible – and where a mistake is caught before it reaches the report. An issue is the accompanying note for open points; Closes #12 in a commit message closes it automatically.

Was nicht hineingehörtWhat must stay out

Ein Repository hält Quellen, nicht Erzeugnisse und keine Daten. Der Grund ist nicht Sparsamkeit: Die Geschichte eines Repositories lässt sich praktisch nicht löschen. Was einmal in einem Commit stand, steht dort weiter – auch wenn die Datei in einem späteren Commit entfernt wird. Für personenbezogene Daten kollidiert das unmittelbar mit dem Recht auf Löschung. A repository holds sources, not products and no data. The reason is not thrift: a repository's history is practically impossible to erase. What once stood in a commit stays there – even when the file is removed in a later commit. For personal data that collides directly with the right to erasure.

Eine .gitignore wirkt nur nach vorn. Eine Datei, die bereits in einem Commit steht, verschwindet dadurch nicht aus der Geschichte – auch nicht, wenn Sie sie nachträglich in die Liste aufnehmen und löschen. Das Umschreiben der Geschichte ist möglich, aber ein zerstörender Vorgang, der alle Klone unbrauchbar macht. Deshalb steht die .gitignore im ersten Commit, nicht im zwanzigsten. A .gitignore only works forward. A file already in a commit does not disappear from the history through it – not even if you add it to the list afterwards and delete it. Rewriting the history is possible but a destructive operation that invalidates every clone. Hence the .gitignore belongs in the first commit, not the twentieth.

Notebooks in GitNotebooks in Git

Ein .ipynb ist keine Textdatei, sondern JSON – und es enthält die Ausgaben mit, Bilder als lange Zeichenketten eingebettet. Daraus folgen vier Ärgernisse, die alle dieselbe Ursache haben: An .ipynb is not a text file but JSON – and it contains the outputs, images embedded as long strings. Four annoyances follow, all with the same cause:

  • Ein geänderter Codebuchstabe erzeugt einen Unterschied über tausende Zeilen, weil sich die Ausgaben mitgeändert haben. Niemand liest so einen Unterschied.One changed character of code produces a diff over thousands of lines, because the outputs changed too. Nobody reads such a diff.
  • Der Ausführungszähler execution_count ändert sich bei jedem Lauf. Es entstehen Unterschiede, obwohl inhaltlich nichts passiert ist.The execution_count changes on every run. Diffs appear even though nothing happened in substance.
  • Eingebettete Bilder blähen das Repository auf; die 100-MiB-Grenze ist schneller erreicht als man denkt.Embedded images inflate the repository; the 100 MiB limit is reached faster than you would think.
  • Ein Merge-Konflikt im JSON macht das Notebook unbrauchbar – es lässt sich danach nicht mehr öffnen.A merge conflict in the JSON makes the notebook unusable – it cannot be opened afterwards.

Dazu kommt ein fünfter Punkt, der über Ärger hinausgeht: In den Ausgaben stehen Daten. Eine df.head()-Ausgabe mit echten Namen wandert beim Push in ein öffentliches Repository und ist damit veröffentlicht. Plus a fifth point that goes beyond annoyance: the outputs contain data. A df.head() output with real names travels into a public repository on push and is thereby published.

Wenn ein Schlüssel entwischtWhen a key escapes

Es passiert – meist über eine .env-Datei, die vor der .gitignore da war, oder über ein Notebook mit einem Schlüssel in einer Code-Zelle. Wichtig ist die Reihenfolge der Reaktion, und sie ist nicht die, die man intuitiv wählt. It happens – usually through a .env file that predated the .gitignore, or through a notebook with a key in a code cell. What matters is the order of the response, and it is not the one intuition suggests.

Fünf Schritte, in dieser ReihenfolgeFive steps, in this order

  1. Den Schlüssel beim Anbieter widerrufen. Sofort, vor allem anderen. Ein widerrufener Schlüssel in einem öffentlichen Repository ist harmlos.Revoke the key with the provider. Immediately, before anything else. A revoked key in a public repository is harmless.
  2. Einen neuen erzeugen und die betroffenen Dienste umstellen.Create a new one and switch the affected services over.
  3. Die Protokolle prüfen: Wurde der Schlüssel in der Zwischenzeit benutzt?Check the logs: was the key used in the meantime?
  4. Die Ursache beheben: .gitignore ergänzen, Schlüssel aus dem Code in eine Umgebungsvariable verschieben.Fix the cause: extend the .gitignore, move the key from the code into an environment variable.
  5. Erst dann über das Umschreiben der Geschichte nachdenken – falls überhaupt nötig.Only then think about rewriting the history – if it is needed at all.

GitHub formuliert es unmissverständlich: Den Schlüssel aus dem Code zu entfernen, einen neuen Commit zu schieben oder das Repository zu löschen und neu anzulegen verhindert nicht, dass er ausgenutzt wird. Nur der Widerruf tut das. GitHub puts it unambiguously: removing the key from the codebase, pushing a new commit, or deleting and recreating the repository does not prevent the secret from being exploited. Only revoking it does.

Zwei Einstellungen, die vorbeugen. Push-Schutz: GitHub erkennt bekannte Schlüsselformate und blockiert den Push, bevor sie ankommen – für Pushes in öffentliche Repositories ist der Schutz für Nutzerkonten standardmäßig aktiv, je Repository lässt er sich unter Settings → Code security einschalten. E-Mail-Adresse verbergen: Ihr Name und Ihre Adresse stehen dauerhaft und öffentlich in jedem Commit. Settings → Emails → Keep my email addresses private setzt eine Ersatzadresse ein. Two settings that prevent trouble. Push protection: GitHub recognises known key formats and blocks the push before they arrive – for pushes to public repositories the protection is on by default for user accounts, and per repository it can be enabled under Settings → Code security. Hide your email address: your name and address sit permanently and publicly in every commit. Settings → Emails → Keep my email addresses private substitutes a no-reply address.

SpielplatzPlayground

Eine Konsole ohne Auftrag, in der git nachgebildet ist. Sie können ein Repository anlegen oder klonen, Dateien anlegen, vormerken, festschreiben, Zweige öffnen und zusammenführen. Der Fernserver ist ebenfalls nachgebildet: git push funktioniert, sobald ein origin eingetragen ist – aber es verlässt nichts diesen Browser. A console without an assignment, with git modelled in it. You can create or clone a repository, create files, stage them, commit, open branches and merge them. The remote is modelled too: git push works once an origin is set – but nothing leaves this browser.

ÜbungenExercises

Sechs Übungen: dreimal an der Konsole – klonen und lesen, eine Änderung festhalten, mit Zweigen arbeiten – und dreimal zum Nachdenken über Begriffe, Ausschlüsse und den Umgang mit einem entwischten Schlüssel. Six exercises: three at the console – clone and read, record a change, work with branches – and three to think through concepts, exclusions and how to handle an escaped key.

ZusammenfassungSummary

  • Git ist das Programm auf Ihrem Rechner, GitHub der Dienst, der Repositories aufbewahrt. Pull Requests und Issues sind GitHub-Funktionen, keine Git-Funktionen.Git is the program on your machine, GitHub the service that hosts repositories. Pull requests and issues are GitHub functions, not Git functions.
  • Drei Bereiche: Arbeitsverzeichnis, Staging, Repository. git add wählt aus, git commit schreibt fest, git push überträgt. git status zeigt, wo Sie stehen – und ist der Befehl, den man am häufigsten braucht.Three areas: working directory, staging, repository. git add selects, git commit records, git push transfers. git status shows where you stand – and is the command needed most often.
  • Ein Zweig ist ein Zeiger, kein Kopiervorgang. Er ist die richtige Antwort auf „was wäre, wenn“ – und ein Konflikt beim Zusammenführen ist eine Frage, keine Störung.A branch is a pointer, not a copy operation. It is the right answer to “what if” – and a merge conflict is a question, not a malfunction.
  • Daten und Geheimnisse gehören nicht ins Repository. Die .gitignore steht im ersten Commit, weil sie nur nach vorn wirkt.Data and secrets do not belong in the repository. The .gitignore goes in the first commit, because it only works forward.
  • Notebooks sind JSON mit eingebetteten Ausgaben. Ohne nbstripout sind Unterschiede unlesbar, Konflikte zerstörend und Ausgaben eine Veröffentlichung.Notebooks are JSON with embedded outputs. Without nbstripout, diffs are unreadable, conflicts destructive and outputs a publication.
  • Ein entwischter Schlüssel wird zuerst widerrufen, nicht zuerst gelöscht. Löschen entfernt ihn aus der Gegenwart, nicht aus der Geschichte – und nicht aus den Kopien, die schon gemacht wurden.An escaped key is revoked first, not deleted first. Deleting removes it from the present, not from the history – and not from the copies already made.
