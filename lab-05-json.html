Es wurde aus der Schreibweise für Objekte in JavaScript herausgelöst und ist heute in RFC 8259 und ECMA-404 festgelegt – zwei Dokumente, dieselbe Grammatik. Sie begegnen ihm an vier Stellen, und alle vier kommen in diesem Kurs vor: JSON (JavaScript Object Notation) is a text format for exchanging structured data. JSON ist Text mit sechs Werttypen und zwei KlammernJSON is text with six value types and two kinds of bracket

Ein JSON-Dokument ist genau ein Wert. Ein Wert ist entweder ein Objekt { … } (Name-Wert-Paare), ein Feld [ … ] (geordnete Liste), eine Zeichenkette, eine Zahl, eines der Literale true/false oder null. Objekte und Felder enthalten wieder Werte – beliebig tief. Mehr gibt es nicht: keine Datumstypen, keine Kommentare, keine Verweise. Alles, was ein System darüber hinaus wissen muss, ist Vereinbarung zwischen Sender und Empfänger. A JSON document is exactly one value. A value is either an object { … } (name/value pairs), an array [ … ] (ordered list), a string, a number, one of the literals true/false or null. Objects and arrays contain values again – to any depth. There is nothing more: no date types, no comments, no references. Everything a system has to know beyond that is an agreement between sender and receiver.

  • Elemente werden mit Komma getrennt; vor der schließenden Klammer steht kein Komma.Elements are separated by commas; there is no comma before the closing bracket.
  • Es gibt keine Kommentare. // und /* */ machen das Dokument ungültig.There are no comments. // and /* */ make the document invalid.
  • Literale sind kleingeschrieben: true, false, null. True, None, NULL, undefined sind keine JSON-Werte.Literals are lower case: true, false, null. True, None, NULL, undefined are not JSON values.
  • Zahlen haben keine führende Null (01 ist ungültig), kein Pluszeichen, keinen Tausenderpunkt; Dezimaltrenner ist der Punkt. NaN und Infinity sind nicht erlaubt.Numbers have no leading zero (01 is invalid), no plus sign, no thousands separator; the decimal separator is the point. NaN and Infinity are not allowed.
  • Ganze Zahlen sind nur bis 253−1 (9007199254740991) verlässlich, weil JavaScript jede Zahl als double liest. 64-Bit-Kennungen werden deshalb als Zeichenkette übertragen.Integers are reliable only up to 253−1 (9007199254740991), because JavaScript reads every number as a double. 64-bit identifiers are therefore transmitted as strings.
  • Es gibt keinen Datumstyp. Datum und Zeit sind Zeichenketten nach ISO 8601: "2024-04-02", "2025-10-05T07:58:00", mit Zeitzone "2026-09-01T06:00:00+02:00".There is no date type. Date and time are strings in ISO 8601: "2024-04-02", "2025-10-05T07:58:00", with time zone "2026-09-01T06:00:00+02:00".

Was daneben stehtWhat stands beside it

Fünf Formate sehen JSON ähnlich oder lösen dieselbe Aufgabe – und jedes davon hat mindestens eine Regel, die JSON nicht kennt. Wer sie verwechselt, bekommt Expecting value: line 1 column 1 (char 0) und sucht den Fehler an der falschen Stelle. Five formats look similar to JSON or solve the same task – and each has at least one rule JSON does not know. Whoever confuses them gets Expecting value: line 1 column 1 (char 0) and looks for the error in the wrong place.

JSON Lines · .jsonl

Ein vollständiger JSON-Wert je Zeile, getrennt durch \n, UTF-8 ohne BOM. Die Datei als Ganzes ist kein JSON – es fehlen die eckigen Klammern und die Kommas. Dafür lässt sich eine Zeile anhängen, ohne die Datei zu lesen, und head, wc -l und grep funktionieren. Standard für Protokolle, Datenströme und Trainingsdaten. fahrten.jsonl enthält die 1.500 Fahrten so; pandas liest sie mit pd.read_json("fahrten.jsonl", lines=True). One complete JSON value per line, separated by \n, UTF-8 without BOM. The file as a whole is not JSON – the square brackets and commas are missing. In return, a line can be appended without reading the file, and head, wc -l and grep work. Standard for logs, data streams and training data. fahrten.jsonl holds the 1,500 rides this way; pandas reads them with pd.read_json("fahrten.jsonl", lines=True).

JSONC · JSON5

JSON mit Kommentaren und nachgestellten Kommas – der Modus, in dem VS Code seine settings.json und tasks.json hält. JSON5 geht weiter: unquotierte Schlüssel, einfache Anführungszeichen, Infinity. Beides ist gedacht für Dateien, die Menschen von Hand pflegen, und beides ist mit json.loads und JSON.parse nicht lesbar. Wer eine settings.json als Vorlage für eine Schnittstellenantwort nimmt, merkt das an Expecting property name enclosed in double quotes. JSON with comments and trailing commas – the mode in which VS Code keeps its settings.json and tasks.json. JSON5 goes further: unquoted keys, single quotes, Infinity. Both are meant for files people maintain by hand, and both are not readable with json.loads and JSON.parse. Whoever takes a settings.json as a template for an interface response notices by Expecting property name enclosed in double quotes.

YAML

Die Sprache von compose.yaml (Lab 07), render.yaml (Lab 11), GitHub Actions und Kubernetes. Struktur durch Einrückung mit Leerzeichen (Tabulatoren sind verboten), Listen mit -, Kommentare mit #. YAML 1.2 ist eine Obermenge von JSON: Jede JSON-Datei ist gültiges YAML, nicht umgekehrt. Stolperstein: Ein Wert ohne Anführungszeichen wird gedeutet – no kann in älteren Parsern zu false werden, 08 zu einer Zahl. The language of compose.yaml (lab 07), render.yaml (lab 11), GitHub Actions and Kubernetes. Structure by indentation with spaces (tabs are forbidden), lists with -, comments with #. YAML 1.2 is a superset of JSON: every JSON file is valid YAML, not the other way round. Stumbling block: an unquoted value gets interpreted – no can become false in older parsers, 08 a number.

TOML

Das Format von pyproject.toml: Abschnitte in eckigen Klammern wie in INI-Dateien, schluessel = wert, Kommentare mit #, und – anders als JSON – ein echter Datumstyp. Python liest es seit 3.11 mit tomllib aus der Standardbibliothek, schreibt es aber nicht. The format of pyproject.toml: sections in square brackets as in INI files, key = value, comments with #, and – unlike JSON – a real date type. Python reads it since 3.11 with tomllib from the standard library, but does not write it.

CSV

Ein Datensatz je Zeile, Felder durch Komma getrennt, Felder mit Komma oder Zeilenumbruch in doppelten Anführungszeichen (RFC 4180). „Es gibt keine formale Spezifikation“, sagt der RFC selbst – und ein deutsches Excel schreibt Semikolon als Trenner und Dezimalkomma. In pandas: pd.read_csv(pfad, sep=";", decimal=","). Keine Typen, keine Verschachtelung, keine Unterscheidung zwischen leer, null und fehlend. One record per line, fields separated by commas, fields containing a comma or line break in double quotes (RFC 4180). “There is no formal specification”, the RFC itself says – and a German Excel writes the semicolon as separator and the decimal comma. In pandas: pd.read_csv(path, sep=";", decimal=","). No types, no nesting, no distinction between empty, null and missing.

Warum CSV keine Verschachtelung kannWhy CSV cannot nest

CSV ist ein zweidimensionales Raster: Jede Zeile hat dieselben Spalten, jede Zelle enthält einen einzelnen Wert. Eine Station mit sechs Rädern passt nicht in eine Zeile – sechs Räder sind sechs Werte, und die Zahl ist von Station zu Station verschieden. Es gibt zwei Auswege, und beide verlieren etwas: Flachklopfen (raeder.0.rad_id, raeder.1.rad_id, … – Spalten, die mit dem längsten Datensatz wachsen und bei kürzeren leer bleiben) oder Normalisieren in mehrere Dateien, die über eine Kennung zusammengehören. Das zweite ist der Weg in die relationale Datenbank und Gegenstand des Abschnitts „Von JSON zur Tabelle“. Umgekehrt kann CSV nicht sagen, ob eine leere Zelle null, "" oder „Spalte gab es nicht“ bedeutet – JSON kann alle drei unterscheiden. CSV is a two-dimensional grid: every row has the same columns, every cell holds a single value. A station with six bikes does not fit in one row – six bikes are six values, and the number differs from station to station. There are two ways out, and both lose something: flattening (raeder.0.rad_id, raeder.1.rad_id, … – columns that grow with the longest record and stay empty for shorter ones) or normalising into several files that belong together via an identifier. The second is the route into the relational database and the subject of the section “From JSON to a table”. Conversely, CSV cannot say whether an empty cell means null, "" or “the column did not exist” – JSON can distinguish all three.

JSON erzeugen und prüfenProducing and checking JSON

JSON schreibt man nicht von Hand, sondern lässt es erzeugen: aus einem dict in Python, aus einem Objekt in JavaScript. Dann stimmen Anführungszeichen und Kommas automatisch – und die verbleibenden Fehler sind die interessanten: Umlaute, Datumswerte, Typen. You do not write JSON by hand but have it generated: from a dict in Python, from an object in JavaScript. Then quotes and commas are automatically right – and the remaining errors are the interesting ones: umlauts, date values, types.

Umlaute: zwei Stellen, an denen es schiefgehtUmlauts: two places where it goes wrong

Erstens beim Öffnen: Ohne encoding="utf-8" nimmt Python die Voreinstellung des Betriebssystems – auf Windows bis Python 3.14 cp1252 (UTF-8 wird erst mit Python 3.15 Standard, PEP 686, Stand 09/2026). Eine UTF-8-Datei, als cp1252 gelesen, zeigt WÃ¼rzburg; eine cp1252-Datei, als UTF-8 gelesen, bricht ab mit UnicodeDecodeError: 'utf-8' codec can't decode byte 0xfc in position …: invalid start byte. Zweitens beim Schreiben: json.dumps maskiert ohne ensure_ascii=False jeden Umlaut als \u00fc – gültig, aber unlesbar. Die Regel: encoding="utf-8" bei jedem open, ensure_ascii=False bei jedem dumps. First when opening: without encoding="utf-8" Python takes the operating system's default – on Windows cp1252 up to Python 3.14 (UTF-8 becomes the default only with Python 3.15, PEP 686, as of 09/2026). A UTF-8 file read as cp1252 shows WÃ¼rzburg; a cp1252 file read as UTF-8 aborts with UnicodeDecodeError: 'utf-8' codec can't decode byte 0xfc in position …: invalid start byte. Second when writing: without ensure_ascii=False, json.dumps escapes every umlaut as \u00fc – valid but unreadable. The rule: encoding="utf-8" on every open, ensure_ascii=False on every dumps.

Ein Schema für die StrukturA schema for the structure

Dass eine Datei gültiges JSON ist, sagt nichts darüber, ob sie die erwartete Struktur hat. {"station_id": "4"} ist gültig – und trotzdem falsch, wenn eine Zahl erwartet wird. Dafür gibt es JSON Schema: ein JSON-Dokument, das beschreibt, welche Schlüssel mit welchen Typen, Mustern und Wertelisten in einem anderen JSON-Dokument stehen müssen.
