PyCharm und WebStormPyCharm and WebStorm

Ein Editor zeigt Text. Eine IDE weiß, welches Python gerade rechnet, welche Pakete es kennt, wo das Projekt anfängt und was seit dem letzten Commit geändert wurde. Dieser Unterschied entscheidet in jedem Analytics-Projekt darüber, ob ein Skript auf dem zweiten Rechner läuft. In diesem Lab legen Sie ein PyCharm-Projekt mit eigener Umgebung an, führen den häufigsten Fehler des Semesters absichtlich herbei – ModuleNotFoundError trotz Installation – und beheben ihn mit einem Blick in die Statusleiste. Danach dasselbe in WebStorm für ein Node-Projekt, denn beide sind dieselbe Plattform. An editor shows text. An IDE knows which Python is computing right now, which packages it knows, where the project begins and what has changed since the last commit. That difference decides, in every analytics project, whether a script runs on the second machine. In this lab you create a PyCharm project with its own environment, deliberately cause the semester's most common error – ModuleNotFoundError despite installation – and fix it with one look at the status bar. Then the same in WebStorm for a Node project, because both are the same platform.

Das Problem, das es löstThe problem it solves

In Lab 01 haben Sie das Terminal kennengelernt, in Lab 02 Git. Beides funktioniert mit jedem Texteditor. Warum also eine IDE? Weil ein Skript, das Daten auswertet, an vier Dinge gebunden ist, die im Editor unsichtbar bleiben: an einen Projektordner (wo liegen die Daten relativ zum Skript?), an einen Interpreter (welches Python, welche Version?), an Abhängigkeiten (welches pandas?) und an einen Stand im Repository. Ein Editor kennt keines davon. Er zeigt import pandas in derselben Farbe, ob pandas installiert ist oder nicht – und meldet den Fehler erst, wenn das Skript läuft. Auf dem eigenen Rechner. Nicht auf dem der Kommilitonin. In lab 01 you met the terminal, in lab 02 Git. Both work with any text editor. So why an IDE? Because a script that analyses data is bound to four things that stay invisible in an editor: a project folder (where is the data relative to the script?), an interpreter (which Python, which version?), dependencies (which pandas?) and a state in the repository. An editor knows none of them. It shows import pandas in the same colour whether pandas is installed or not – and reports the error only when the script runs. On your own machine. Not on your fellow student's.

Eine Integrated Development Environment hält diese vier Dinge zusammen und zeigt sie an: den Interpreter in der Statusleiste, fehlende Pakete als Unterstreichung, das Arbeitsverzeichnis in der Run Configuration, die Änderungen im Commit tool window. In diesem Kurs sind das zwei Produkte von JetBrains: PyCharm für Python und Datenarbeit (Lab 06, Lab 10) und WebStorm für JavaScript und Node (Lab 11). Beide bauen auf derselben Plattform auf – gleiche Menüs, gleiche Tastenkürzel, gleiches Git-Fenster, gleicher Trust-Dialog. Wer eine bedienen kann, kann beide. Das Gegenstück ohne Installation ist Colab in Lab 04: ein Notebook im Browser, das keinen Interpreter kennt, weil Google ihn stellt. An integrated development environment keeps these four things together and shows them: the interpreter in the status bar, missing packages as an underline, the working directory in the Run Configuration, the changes in the Commit tool window. In this course these are two JetBrains products: PyCharm for Python and data work (labs 06, 10) and WebStorm for JavaScript and Node (lab 11). Both are built on the same platform – same menus, same shortcuts, same Git window, same trust dialog. Whoever can operate one can operate both. The counterpart without installation is Colab in lab 04: a notebook in the browser that knows no interpreter because Google provides it.

Projekt = Ordner + .idea + InterpreterProject = folder + .idea + interpreter

Ein PyCharm-Projekt ist nichts Geheimnisvolles: ein gewöhnlicher Ordner, in dem die IDE einen versteckten Unterordner .idea mit ihrer Konfiguration anlegt, plus ein Interpreter, der diesem Ordner zugeordnet ist – im Kurs immer eine virtuelle Umgebung .venv im selben Ordner. Fehlt eine der drei Zutaten, hat das einen eigenen Namen: kein .idea heißt „nur ein Ordner“, kein Interpreter heißt Banner No Python interpreter configured for the project, ein anderer Interpreter als gedacht heißt ModuleNotFoundError. A PyCharm project is nothing mysterious: an ordinary folder in which the IDE creates a hidden subfolder .idea with its configuration, plus an interpreter assigned to this folder – in the course always a virtual environment .venv in the same folder. If one of the three ingredients is missing, it has its own name: no .idea means “just a folder”, no interpreter means the banner No Python interpreter configured for the project, a different interpreter than intended means ModuleNotFoundError.

Ein Projekt anlegenCreating a project

Der erste Handgriff, und der einzige, bei dem ein Dialog alle drei Zutaten auf einmal erzeugt: Ordner, .idea und Interpreter. Bevor Sie ihn öffnen, eine Entscheidung, die sich später nur mühsam korrigieren lässt – der Ort. Projektordner gehören in einen Pfad ohne Umlaute und Leerzeichen und nicht in einen Ordner, den OneDrive, iCloud Drive oder die Desktop-Synchronisation verwaltet. Beides ist unter Windows leicht verletzt: C:\Users\Jörg\OneDrive - Persönlich\Desktop bricht gleich drei Regeln. Im Kurs gilt ~/dev/… auf dem Mac und C:\dev\… unter Windows; synchronisiert wird über Git (Lab 02), nicht über die Cloud. The first move, and the only one where a dialog produces all three ingredients at once: folder, .idea and interpreter. Before you open it, a decision that is hard to correct later – the location. Project folders belong in a path without umlauts and spaces and not in a folder managed by OneDrive, iCloud Drive or desktop synchronisation. Both are easily violated on Windows: C:\Users\Jörg\OneDrive - Persönlich\Desktop breaks three rules at once. In the course it is ~/dev/… on the Mac and C:\dev\… on Windows; synchronisation happens via Git (lab 02), not via the cloud.

Fremdes Projekt öffnen: der Trust-DialogOpening a foreign project: the trust dialog

Beim ersten Öffnen eines Ordners, der nicht von Ihnen stammt – ein Klon aus GitHub, ein heruntergeladenes Beispiel – fragt die IDE: Trust Project, Preview in Safe Mode oder Don't Open. Der Grund: Ein Projekt kann Anweisungen enthalten, die die IDE beim Öffnen ausführt. Safe Mode zeigt nur an, ohne etwas auszuführen. Für Kursrepositories ist Trust Project richtig; das Häkchen „Trust all projects in '…' folder“ für den eigenen dev-Ordner erspart die Frage künftig. Verwaltet unter Settings → Appearance & Behavior → Trusted Locations. On first opening a folder that is not yours – a clone from GitHub, a downloaded example – the IDE asks: Trust Project, Preview in Safe Mode or Don't Open. The reason: a project can contain instructions the IDE executes on opening. Safe Mode only displays, without running anything. For course repositories Trust Project is right; the checkbox “Trust all projects in '…' folder” for your own dev folder saves the question in future. Managed under Settings → Appearance & Behavior → Trusted Locations.

Indexing: warten oder ausschließenIndexing: wait or exclude

Nach dem Öffnen liest die IDE jede Datei des Ordners, um Code Completion und Navigation anzubieten. Bei Quellcode dauert das Sekunden. Bei einem Ordner mit 400 MB JSON-Export (Lab 05) oder einer SQLite-Datei (Lab 06) dauert es Minuten – und wiederholt sich bei jeder Änderung. Abhilfe: Rechtsklick auf den Datenordner → Mark Directory as → Excluded. Die Dateien bleiben lesbar und die Skripte finden sie; nur die IDE hört auf, sie zu analysieren. .venv schließt PyCharm von selbst aus. After opening, the IDE reads every file in the folder to offer completion and navigation. For source code that takes seconds. For a folder with a 400 MB JSON export (lab 05) or an SQLite file (lab 06) it takes minutes – and repeats on every change. Remedy: right-click the data folder → Mark Directory as → Excluded. The files stay readable and the scripts find them; only the IDE stops analysing them. .venv is excluded by PyCharm itself.

Der InterpreterThe interpreter

Auf jedem Rechner gibt es mehrere Pythons: das des Betriebssystems, eines aus dem Installer, vielleicht Anaconda – und je Projekt eine .venv. Jedes hat seinen eigenen Paketordner. pip install pandas installiert in genau das Python, zu dem dieses pip gehört; ein anderes Python weiß davon nichts. Daraus folgt die Meldung, die jedes Semester die meiste Zeit kostet: ModuleNotFoundError: No module named 'pandas' – obwohl die Installation gerade Erfolg gemeldet hat. Nichts ist kaputt. Es wurde nur in eine andere Umgebung installiert als die, die das Skript ausführt. Every machine has several Pythons: the operating system's, one from the installer, perhaps Anaconda – and a .venv per project. Each has its own package folder. pip install pandas installs into exactly the Python this pip belongs to; another Python knows nothing about it. From that follows the message that costs the most time every semester: ModuleNotFoundError: No module named 'pandas' – although the installation just reported success. Nothing is broken. It was merely installed into a different environment than the one running the script.

Die IDE zeigt die Antwort immer an derselben Stelle: unten rechts in der Statusleiste. Dort steht der Interpreter des Projekts, etwa Python 3.12 (velocity); ein Klick darauf zeigt den Pfad und erlaubt den Wechsel – Add New Interpreter → Add Local Interpreter für eine neue Umgebung, oder eine vorhandene aus der Liste. Fehlt der Interpreter ganz, erscheint im Editor das Banner No Python interpreter configured for the project mit dem Link Configure Python interpreter. Beides führt in denselben Dialog. The IDE shows the answer always in the same place: bottom right in the status bar. There stands the project's interpreter, such as Python 3.12 (velocity); clicking it shows the path and allows switching – Add New Interpreter → Add Local Interpreter for a new environment, or an existing one from the list. If the interpreter is missing entirely, the editor shows the banner No Python interpreter configured for the project with the link Configure Python interpreter. Both lead into the same dialog.

Die eine Entscheidung, die Sie treffen müssen, betrifft .idea. JetBrains dokumentiert: Die Dateien in .idea gehören unter Versionskontrolle, mit Ausnahme von workspace.xml, die lokale Vorlieben enthält; PyCharm legt beim Anlegen eines Repositories selbst eine .idea/.gitignore an. The one decision you have to make concerns .idea. JetBrains documents: the files in .idea belong under version control, except workspace.xml, which holds local preferences; PyCharm itself creates an .idea/.gitignore when creating a repository. That is meant for teams wanting to share the same IDE configuration. Course rule: the whole .idea/ and the whole .venv/ stay out. The reason is practical: .idea contains the path to the interpreter, and on your machine that reads /Users/anna/dev/velocity/.venv and on your fellow student's C:\dev\velocity\.venv. Merging produces conflicts in files nobody wrote. The .venv, in turn, is large, operating-system-dependent and recreated in a minute from requirements.txt.

OneDrive · iCloud

Ein Projekt in einem synchronisierten Ordner verliert seinen Interpreter „von selbst“, das Indexing hängt, und beim Speichern erscheinen Fehler – weil .idea, .venv und __pycache__ mitsynchronisiert und dabei gesperrt werden. Cloud-Laufwerke sind von JetBrains nicht offiziell unterstützt. Abhilfe: Projekt nach ~/dev bzw. C:\dev verschieben, .venv neu anlegen, synchronisieren über Git. A project in a synchronised folder loses its interpreter “by itself”, indexing hangs, and errors appear on saving – because .idea, .venv and __pycache__ get synchronised and locked in the process. Cloud drives are not officially supported by JetBrains. Remedy: move the project to ~/dev or C:\dev, recreate .venv, synchronise via Git.

Umlaut · LeerzeichenUmlaut · space

Ein Pfad wie C:\Users\Jörg\Meine Projekte lässt die Aktivierung der .venv scheitern – mit UnicodeDecodeError, einem unlesbaren activate.bat oder Zitatfehlern im Interpreter-Pfad. Das ist ein Problem von Python und Windows, nicht von PyCharm, aber es trifft Sie in PyCharm. Regel: nur ASCII, keine Leerzeichen – im Projektpfad und möglichst auch im Benutzernamen. A path such as C:\Users\Jörg\Meine Projekte makes the activation of the .venv fail – with UnicodeDecodeError, an unreadable activate.bat or quoting errors in the interpreter path. That is a Python and Windows problem, not a PyCharm one, but it hits you in PyCharm. Rule: ASCII only, no spaces – in the project path and preferably in the user name too.

Microsoft Defender

Unter Windows erscheint die Meldung Microsoft Defender may affect IDE: Der Echtzeitschutz bremst Indexing und das Anlegen der .venv. Die Knöpfe heißen Automatically, How to configure manually, Ignore for this project und Never ask again. „Automatically“ verlangt Administratorrechte – auf dem privaten Laptop in Ordnung, auf Pool-Rechnern nicht möglich; dort ist „Ignore for this project“ die richtige Antwort. Es ist ein Hinweis zur Geschwindigkeit, kein Fehler. On Windows the notification Microsoft Defender may affect IDE appears: real-time protection slows indexing and the creation of the .venv. The buttons are Automatically, How to configure manually, Ignore for this project and Never ask again. “Automatically” needs administrator rights – fine on a private laptop, not possible on pool machines; there “Ignore for this project” is the right answer. It is a performance notice, not an error.
