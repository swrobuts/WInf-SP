Die Kommandozeile The command line

Kein Werkzeug dieses Kurses lässt sich lange ohne Konsole benutzen. Git spricht in Befehlen, Docker ausschließlich, jede Python-Umgebung wird dort aktiviert, und wenn eine Installationsanleitung eine Zeile in grauem Kasten zeigt, gehört sie hierher. Die gute Nachricht: Es sind etwa zwölf Befehle, und die Hälfte davon dient nur dazu, sich zu orientieren. Die Konsole auf dieser Seite ist nachgebildet – sie richtet keinen Schaden an, weist aber genauso hart zurück wie die echte. No tool in this course can be used for long without a console. Git speaks in commands, Docker exclusively so, every Python environment is activated there, and when an installation guide shows a line in a grey box, that line belongs here. The good news: there are about twelve commands, and half of them serve only to find your bearings. The console on this page is a model – it does no damage, but it rejects mistakes just as harshly as the real one.

pwd · ls · cd mkdir · touch · echo cat · cp · mv · rm Absolute und relative PfadeAbsolute and relative paths zsh · PowerShell · cmd.exe

Warum überhaupt tippen?Why type at all?

Ein grafisches Fenster zeigt, was gerade da ist. Eine Befehlszeile beschreibt, was getan werden soll – und lässt sich deshalb aufschreiben, weitergeben, wiederholen und in ein Skript legen. Genau darin liegt ihr Wert für Analytics: Eine Auswertung, die aus zwölf Mausklicks besteht, ist morgen nicht mehr nachvollziehbar; dieselbe Auswertung als drei Zeilen Text ist es in fünf Jahren noch. A graphical window shows what is currently there. A command line describes what should be done – and can therefore be written down, passed on, repeated and put into a script. That is precisely where its value for analytics lies: an analysis consisting of twelve mouse clicks is no longer traceable tomorrow; the same analysis as three lines of text still is in five years.

Drei Shells, ein PrinzipThree shells, one principle

Was Befehle annimmt und ausführt, heißt Shell. Auf dem Mac ist es standardmäßig zsh, unter Linux meist bash – beide sind sich so ähnlich, dass die Unterschiede hier keine Rolle spielen. Unter Windows gibt es zwei: PowerShell als heutige Standard-Shell und die alte Eingabeaufforderung (cmd.exe), die in älteren Anleitungen noch auftaucht. Das Prinzip ist überall dasselbe: Befehl, dann Optionen, dann Gegenstand. Nur die Namen unterscheiden sich – und PowerShell hat für die wichtigsten sogar dieselben Kurznamen wie die Unix-Shells eingebaut. What accepts and executes commands is called a shell. On a Mac it is zsh by default, on Linux usually bash – so similar that the differences do not matter here. Windows has two: PowerShell as today's standard shell and the old Command Prompt (cmd.exe), which still appears in older guides. The principle is the same everywhere: command, then options, then object. Only the names differ – and PowerShell even has the same short names built in as the Unix shells for the most important ones.

Der Schalter über jeder Befehlskarte entscheidet, welche Fassung Sie sehen. Er gilt für die ganze Lernumgebung und merkt sich Ihre Wahl. The switch above each command card decides which version you see. It applies across the whole environment and remembers your choice.

Wie sieht die Aufforderung aus?What does the prompt look like?

Ganz links steht die Eingabeaufforderung (der Prompt). Sie sagt, wer Sie sind und wo Sie sind. In dieser Lernumgebung ist sie nachgebaut: studi@macbook velocity % auf dem Mac, PS C:\Users\studi\velocity> in PowerShell, C:\Users\studi\velocity> in der Eingabeaufforderung. Was Sie in Anleitungen als $, % oder > am Zeilenanfang sehen, ist der Prompt und wird nicht mit abgetippt. Das ist der häufigste Anfängerfehler überhaupt. On the far left sits the prompt. It says who you are and where you are. In this environment it is rebuilt: studi@macbook velocity % on the Mac, PS C:\Users\studi\velocity> in PowerShell, C:\Users\studi\velocity> in Command Prompt. What you see in guides as $, % or > at the start of a line is the prompt and is not typed along. That is the single most common beginner's mistake.

Eine Befehlszeile lesenReading a command line

Jede Zeile hat drei Teile, und sie stehen immer in derselben Reihenfolge. Every line has three parts, and they always come in the same order.

ls -la Downloads │ │ │ │ │ └── Gegenstand: worauf der Befehl wirkt (Datei, Ordner, Image, Branch …) │ └──────── Optionen: verändern das Verhalten, beginnen mit - oder -- └───────────── Befehl: das Programm, das etwas tut

Optionen mit einem Bindestrich sind Kürzel und lassen sich zusammenfassen: -la ist dasselbe wie -l -a. Optionen mit zwei Bindestrichen sind ausgeschrieben: --all. In PowerShell heißen sie Parameter und tragen einen einzelnen Bindestrich mit ausgeschriebenem Namen: -Recurse, -Force. Die Logik bleibt gleich. Options with one dash are abbreviations and can be combined: -la is the same as -l -a. Options with two dashes are spelled out: --all. In PowerShell they are called parameters and carry a single dash with a spelled-out name: -Recurse, -Force. The logic stays the same.

Leerzeichen trennen – auch in OrdnernamenSpaces separate – in folder names too

Die Shell zerlegt die Zeile an Leerzeichen. Ein Ordner namens Analytische Begrifflichkeiten wird deshalb als zwei Gegenstände gelesen und der Befehl scheitert. Zwei Auswege: in Anführungszeichen setzen (cd "Analytische Begrifflichkeiten") oder das Leerzeichen mit einem Rückstrich schützen (cd Analytische\ Begrifflichkeiten). Der eigentliche Rat lautet allerdings: in Projektordnern keine Leerzeichen und keine Umlaute verwenden. Dasselbe stand schon in den Empfehlungen zum Aufbau von Datentabellen – und aus demselben Grund. The shell splits the line at spaces. A folder called Analytical Terminology is therefore read as two objects and the command fails. Two ways out: put it in quotes (cd "Analytical Terminology") or protect the space with a backslash (cd Analytical\ Terminology). The actual advice, though, is: use no spaces and no umlauts in project folders. The same already stood in the recommendations for building data tables – and for the same reason.

Wo bin ich?Where am I?

Eine Konsole steht immer in einem Ordner, dem Arbeitsverzeichnis. Alles, was Sie ohne vollständigen Pfad angeben, wird dort gesucht. Wer sich das nicht klarmacht, sucht später eine halbe Stunde eine Datei, die längst geschrieben ist – nur an anderer Stelle. A console always stands in a folder, the working directory. Everything you name without a full path is looked for there. Whoever loses sight of this later spends half an hour looking for a file that has long been written – just in a different place.

PfadePaths

Ein absoluter Pfad beginnt an der Wurzel und gilt überall gleich. Ein relativer Pfad beginnt im Arbeitsverzeichnis und bedeutet je nach Standort etwas anderes. Vier Zeichen genügen, um sich zu bewegen: An absolute path starts at the root and means the same everywhere. A relative path starts in the working directory and means something different depending on where you stand. Four symbols are enough to move around:

Der Trick mit dem ZiehenThe drag trick

Statt einen langen Pfad abzutippen: cd tippen, ein Leerzeichen, dann den Ordner aus dem Finder in das Terminalfenster ziehen. Enthält der Pfad Leerzeichen, setzt das Terminal Maskierungen mit Rückstrich – er wird also auch dann richtig gelesen. Instead of typing a long path: type cd, a space, then drag the folder from Finder into the terminal window. If the path contains spaces, Terminal adds backslash escapes – so it is read correctly even then.

Statt einen langen Pfad abzutippen: cd tippen, ein Leerzeichen, dann den Ordner aus dem Explorer in das Fenster ziehen. Der Pfad erscheint in Anführungszeichen, wenn er Leerzeichen enthält – lassen Sie sie stehen. Alternativ in der Adresszeile des Explorers cmd oder powershell eintippen: Das Fenster öffnet direkt in diesem Ordner. Instead of typing a long path: type cd, a space, then drag the folder from File Explorer into the window. The path appears in quotation marks if it contains spaces – leave them in place. Alternatively type cmd or powershell into Explorer's address bar: the window opens directly in that folder.

AnlegenCreating things

Ordner und leere Dateien entstehen mit einem Befehl. Hier zeigt sich zum ersten Mal, dass PowerShell einen anderen Weg geht: Es kennt für alles ein New-Item mit Typangabe, hat aber die Unix-Kürzel als Aliase eingebaut. Folders and empty files come into being with one command. This is the first place where PowerShell goes its own way: it has a single New-Item with a type for everything, but it does have the Unix short names built in as aliases.

Das Zeichen > heißt Umleitung: Was der Befehl links davon ausgeben würde, wird stattdessen in die Datei rechts davon geschrieben. Ein einzelnes > überschreibt, ein doppeltes >> hängt an. Der Unterschied ist beim Schreiben von Protokolldateien der zwischen „nur der letzte Lauf“ und „alle Läufe“. The symbol > means redirection: what the command to its left would print is written into the file to its right instead. A single > overwrites, a double >> appends. When writing log files the difference is the one between “only the last run” and “all runs”.

LesenReading

Bevor man eine CSV-Datei in ein Notebook lädt, lohnt ein Blick auf die ersten Zeilen: Welches Trennzeichen? Gibt es eine Kopfzeile? Steht das Dezimalkomma als Komma? Diese drei Fragen kostet die Konsole zwei Sekunden und ein Notebook fünf Minuten. Before loading a CSV file into a notebook, a look at the first lines pays off: which separator? Is there a header row? Is the decimal mark a comma? Those three questions cost the console two seconds and a notebook five minutes.

Kopieren, verschieben, löschenCopy, move, delete

Umbenennen und Verschieben ist derselbe Befehl – das ist kein Zufall, sondern folgt daraus, dass ein Dateiname nur ein Eintrag in einem Ordner ist. Und dann ist da noch rm. Renaming and moving is the same command – no coincidence, but a consequence of a file name being just an entry in a folder. And then there is rm.

Es gibt keinen PapierkorbThere is no wastebasket

Was auf der Kommandozeile gelöscht wird, ist gelöscht. Kein Dialog, keine Rückfrage, kein Papierkorb, kein ⌘Z. Drei Gewohnheiten, die das entschärfen: erst ls auf denselben Ausdruck anwenden, den Sie löschen wollen, und die Ausgabe lesen. rm -rf nie in Kombination mit einem Sternchen tippen, ohne die Zeile vorher laut zu lesen. Und keine Löschbefehle aus dem Netz kopieren, deren Wirkung Sie nicht Zeichen für Zeichen erklären können. What is deleted on the command line is deleted. No dialogue, no confirmation, no wastebasket, no ⌘Z. Three habits that defuse this: first run ls on the very expression you intend to delete, and read the output. Never type rm -rf together with an asterisk without reading the line aloud first. And never copy deletion commands from the internet whose effect you cannot explain character by character.

Handgriffe, die Zeit sparenHabits that save time

Tab

Anfang eines Namens tippen, Tab drücken – die Shell vervollständigt. Passt mehr als eines, zeigt ein zweites Tab die Möglichkeiten. Das ist nicht nur schneller, es ist auch der beste Tippfehlerschutz: Was sich vervollständigen lässt, existiert. Type the beginning of a name, press Tab – the shell completes it. If more than one matches, a second Tab shows the options. This is not only faster, it is the best protection against typos: what can be completed exists.

↑ ↓

Die Pfeiltasten blättern durch die letzten Befehle. Einen langen Befehl, der an einem Tippfehler gescheitert ist, holt man so zurück und korrigiert ihn, statt ihn neu zu tippen. Funktioniert auch in der Konsole auf dieser Seite. The arrow keys page through the last commands. A long command that failed on a typo is brought back and corrected this way instead of retyped. Works in the console on this page too.

Ctrl + C

Bricht ab, was gerade läuft. Nicht „Kopieren“ – das ist im Terminal ⌘C beziehungsweise Ctrl+Shift+C. Wenn ein Befehl scheinbar hängt, ist Ctrl+C der Ausweg. Aborts whatever is running. Not “copy” – that is ⌘C or Ctrl+Shift+C in a terminal. When a command appears to hang, Ctrl+C is the way out.

Groß und kleinUpper and lower case

macOS und Linux unterscheiden bei Befehlen streng zwischen Groß- und Kleinschreibung: LS ist nicht ls. Bei Dateinamen ist macOS standardmäßig nachsichtig, Linux nicht – weshalb ein Notebook, das auf dem Mac läuft, im Container scheitern kann. Windows ist überall nachsichtig. macOS and Linux distinguish case strictly for commands: LS is not ls. For file names macOS is lenient by default, Linux is not – which is why a notebook that runs on the Mac can fail in a container. Windows is lenient everywhere.

Fehler lesenReading errors

Fehlermeldungen der Konsole sind knapp, aber präzise. No such file or directory heißt: falscher Ort oder falscher Name – nicht „defekt“. Permission denied heißt: der Ort ist richtig, die Rechte fehlen. command not found heißt: das Programm ist nicht installiert oder nicht im Suchpfad. Drei Meldungen, drei völlig verschiedene Ursachen. Console error messages are terse but precise. No such file or directory means: wrong place or wrong name – not “broken”. Permission denied means: the place is right, the rights are missing. command not found means: the program is not installed or not on the search path. Three messages, three completely different causes.

Hilfe im WerkzeugHelp inside the tool

Fast jeder Befehl erklärt sich selbst: ls --help, git --help, docker run --help. Ausführlicher unter macOS und Linux man ls (verlassen mit q), in PowerShell Get-Help Get-ChildItem. Das ist keine Notlösung, sondern die verlässlichste Quelle – sie beschreibt genau die Fassung, die bei Ihnen installiert ist. Almost every command explains itself: ls --help, git --help, docker run --help. In more detail on macOS and Linux man ls (leave with q), in PowerShell Get-Help Get-ChildItem. This is not a last resort but the most reliable source – it describes exactly the version installed on your machine.
