Bibliothek, nicht ServerA library, not a server

Eine Datenbank, wie Sie sie aus DABA kennen, ist ein Programm, das im Hintergrund läuft: Es nimmt Verbindungen an, prüft Zugangsdaten, verwaltet Sitzungen. SQLite ist nichts davon. SQLite ist eine Bibliothek – ein Stück Code, das ein Programm einbindet und das eine Datei liest und schreibt. Es gibt keinen Dienst, den man starten könnte, keinen Port, kein Passwort. Die Dokumentation sagt es selbst: SQLite konkurriert nicht mit Oracle oder PostgreSQL, sondern mit fopen() – mit dem Öffnen einer Datei. A database as you know it from DABA is a program running in the background: it accepts connections, checks credentials, manages sessions. SQLite is none of that. SQLite is a library – a piece of code a program embeds and that reads and writes a file. There is no service to start, no port, no password. The documentation says so itself: SQLite does not compete with Oracle or PostgreSQL but with fopen() – with opening a file.

Eine Datei, ein SchreiberOne file, one writer

Die ganze Datenbank – Tabellen, Indizes, Sichten, Daten – ist eine Datei, meist mit der Endung .db oder .sqlite. Sie lässt sich kopieren, per E-Mail verschicken, in ein Repository legen. Und weil es keinen Dienst gibt, der die Zugriffe ordnet, gilt eine Regel auf Dateiebene: Zu jedem Zeitpunkt darf genau ein Prozess schreiben. Lesen dürfen viele, aber der zweite Schreiber wartet – oder bekommt database is locked. The whole database – tables, indexes, views, data – is one file, usually with the extension .db or .sqlite. It can be copied, emailed, put into a repository. And since there is no service arbitrating access, one rule applies at file level: at any instant exactly one process may write. Many may read, but the second writer waits – or gets database is locked.

Der WAL-Modus (PRAGMA journal_mode = WAL) lockert das: Leser blockieren dann keinen Schreiber mehr und umgekehrt. Es bleibt aber bei einem Schreiber – und WAL funktioniert nur, wenn alle Prozesse auf demselben Rechner laufen. Auf einem Netzlaufwerk oder in einem OneDrive-Ordner ist die Sperre unzuverlässig; die Datei kann beschädigt werden. WAL mode (PRAGMA journal_mode = WAL) relaxes that: readers then no longer block a writer and vice versa. It stays at one writer, though – and WAL works only when all processes run on the same machine. On a network drive or in a OneDrive folder the lock is unreliable; the file can get corrupted.

Dafür ist SQLite gemachtWhat SQLite is made for

  • Anwendungsdateiformat: Statt eines eigenen Formats speichert ein Programm seine Daten in einer SQLite-Datei – Fotoverwaltungen, Browserprofile, Nachrichten-Apps.Application file format: instead of its own format a program stores its data in a SQLite file – photo managers, browser profiles, messaging apps.
  • Lehre und Tests: eine Datei je Person, kein Konto, kein Server – dieses Lab.Education and testing: one file per person, no account, no server – this lab.
  • Kleine Websites mit wenigen Schreibzugriffen; die Dokumentation nennt als Faustregel bis zu 100.000 Aufrufe am Tag.Small websites with few writes; the documentation's rule of thumb is up to 100,000 hits a day.

Dafür nichtWhat it is not made for

  • Viele gleichzeitige Schreiber – ein Ticketsystem, ein Shop, eine App mit tausend Nutzern. Ab hier: Lab 07, Lab 08.Many concurrent writers – a ticket system, a shop, an app with a thousand users. From here on: lab 07, lab 08.
  • Netzlaufwerke und Synchronisationsordner (OneDrive, SharePoint, NAS), von mehreren Rechnern gleichzeitig geöffnet – die Sperre versagt, die Datei kann kaputtgehen.Network drives and sync folders (OneDrive, SharePoint, NAS) opened from several machines at once – the lock fails, the file can break.
  • Rechteverwaltung: Wer die Datei lesen darf, darf alles lesen. GRANT und REVOKE sind nicht implementiert.Permission management: whoever may read the file may read everything. GRANT and REVOKE are not implemented.
  • Ein Web Service auf Render (Lab 11): Die Platte dort ist flüchtig, die Datei ist nach jedem Redeploy weg.A web service on Render (lab 11): the disk there is ephemeral, the file is gone after every redeploy.

Das TypsystemThe type system

Hier liegt der eigentliche Unterschied zu allem, was DABA über Datentypen gesagt hat. SQLite kennt fünf Speicherklassen – NULL, INTEGER, REAL, TEXT, BLOB –, und sie beschreiben den Wert, nicht die Spalte. Eine Spalte hat nur eine Affinity, einen Wunsch: Passt der Wert verlustfrei hinein, wird er gewandelt; sonst wird er gespeichert, wie er kam. 'abc' in einer INTEGER-Spalte ist kein Fehler, sondern ein Text in einer Integer-Spalte. Die Dokumentation nennt das ausdrücklich ein Feature. Here lies the real difference from everything DABA said about data types. SQLite has five storage classes – NULL, INTEGER, REAL, TEXT, BLOB – and they describe the value, not the column. A column has only an affinity, a preference: if the value fits losslessly it is converted; otherwise it is stored as it came. 'abc' in an INTEGER column is not an error but a text in an integer column. The documentation expressly calls that a feature.

Welche Affinity eine Spalte bekommt, entscheiden fünf Regeln über den Namen des Typs – in dieser Reihenfolge, die erste passende gewinnt: Which affinity a column gets is decided by five rules over the type's name – in this order, the first match wins:

NUMERIC(6,2) ist in SQLite ein REAL – Geld in CentNUMERIC(6,2) is a REAL in SQLite – money in cents

In SQLite landet derselbe Typname bei Regel 5, ein Wert wie 1.1 wird als binärer Gleitkommawert gespeichert, und Summen tragen Reste wie 1522.5000000000002. Doppelte AnführungszeichenDouble quotes
