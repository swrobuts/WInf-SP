Supabase

In Lab 07 haben Sie eine Datenbank selbst betrieben. Hier betreibt sie jemand anderes – und darunter arbeitet dasselbe PostgreSQL: dieselben Datentypen, dieselben Sichten, dieselben Erweiterungen. Das Neue ist nicht SQL, sondern die Zugriffskontrolle: Sie liegt in der Datenbank selbst, und wer das übersieht, stellt seine Tabelle ins offene Netz. Dieses Lab führt durch die Inbetriebnahme, die zwei Schlüsselarten und die Regel, mit der eine Tabelle abgesichert wird. In lab 07 you ran a database yourself. Here somebody else runs it – and underneath sits the same PostgreSQL: same data types, same views, same extensions. What is new is not SQL but access control: it lives in the database itself, and whoever overlooks that puts their table on the open internet. This lab walks through setting it up, the two kinds of key and the rule that secures a table.

Postgres, gehostetPostgres, hosted

Supabase ist eine quelloffene Entwicklungsplattform, die eine verwaltete PostgreSQL-Datenbank mit den Diensten bündelt, die Anwendungen darum herum brauchen: Benutzerverwaltung, aus dem Schema erzeugte Schnittstellen, Dateiablage, Benachrichtigungen über Änderungen. Für diesen Kurs ist vor allem eines wichtig: Der SQL-Zugang bleibt offen, weil darunter ein vollständiges PostgreSQL arbeitet. Was Sie in DABA über SQL gelernt haben, gilt hier unverändert. Supabase is an open-source development platform bundling a managed PostgreSQL database with the services applications need around it: user management, interfaces generated from the schema, file storage, change notifications. For this course one thing matters above all: the SQL access stays open, because a complete PostgreSQL works underneath. What you learned about SQL in DABA applies here unchanged.

Daten hineinbekommenGetting data in

Drei Wege, mit einer Grenze und einer Falle. Die Grenze: Der Import über die Weboberfläche endet bei 100 MB. Die Falle: Nach einem CSV-Import stehen die Spaltentypen oft auf text, auch wo Zahlen oder Datumsangaben stehen – und dann scheitert jede Aggregation, ohne dass die Ursache offensichtlich ist. Three routes, with one limit and one trap. The limit: import through the web interface stops at 100 MB. The trap: after a CSV import the column types are often text, even where numbers or dates stand – and then every aggregation fails without the cause being obvious.

Der verlässliche Weg ist der umgekehrte: zuerst die Tabelle mit richtigen Typen anlegen, dann importieren. Zwanzig Sekunden mehr Arbeit, und die Prüfung SELECT pg_typeof(preis_eur) FROM fahrt LIMIT 1; bestätigt es in einer Zeile. Dieselbe Sorgfalt, die die Vorlesung unter „Empfehlungen für den Aufbau von Datentabellen“ verlangt: einheitliche Formate, keine Sonderzeichen, kurze Bezeichnungen. The reliable route is the reverse: first create the table with the right types, then import. Twenty seconds more work, and the check SELECT pg_typeof(preis_eur) FROM fahrt LIMIT 1; confirms it in one line. The same care the lecture demands under “recommendations for building data tables”: uniform formats, no special characters, short names.

Row Level SecurityRow level security

Das ist der Abschnitt, der über Lab 07 hinausgeht. Supabase erzeugt aus Ihrem Schema eine Schnittstelle, über die jede Tabelle über das Internet ansprechbar ist. Ob eine Anfrage Zeilen zurückbekommt, entscheidet nicht die Anwendung und nicht der Schlüssel, sondern eine Regel in der Datenbank. Neue Tabellen im Schema public starten dabei mit Rechten für die Rollen, die von außen zugreifen – solange Row Level Security nicht eingeschaltet ist. This is the section that goes beyond lab 07. Supabase generates an interface from your schema through which every table is addressable over the internet. Whether a request gets rows back is decided not by the application and not by the key but by a rule inside the database. New tables in the public schema start with permissions for the roles that access from outside – as long as row level security is not switched on.

Die Regel in einer ZeileThe rule in one line

Nach jedem CREATE TABLE folgt ALTER TABLE … ENABLE ROW LEVEL SECURITY;. Danach liefert die Schnittstelle keine Zeile mehr, bis Sie eine Regel schreiben. Das wirkt wie ein Fehler und ist die richtige Voreinstellung: Standardmäßig verweigern, ausdrücklich erlauben. After every CREATE TABLE comes ALTER TABLE … ENABLE ROW LEVEL SECURITY;. Afterwards the interface returns no row until you write a rule. That looks like an error and is the right default: deny by default, permit explicitly.

USING filtert vorhandene Zeilen – für SELECT, UPDATE und DELETE. WITH CHECK prüft neue oder geänderte Zeilen – für INSERT und UPDATE. Wer die beiden verwechselt, schreibt eine Regel, die alles lesen lässt und nichts einfügen – oder umgekehrt. USING filters existing rows – for SELECT, UPDATE and DELETE. WITH CHECK checks new or changed rows – for INSERT and UPDATE. Whoever confuses the two writes a rule that lets everything be read and nothing inserted – or the reverse.

Prüfen lässt sich der Zustand ohne SQL: Advisors → Security Advisor listet jede Tabelle, für die Row Level Security nicht eingeschaltet ist. Diese Liste sollte leer sein, bevor ein Projekt jemandem gezeigt wird. The state can be checked without SQL: Advisors → Security Advisor lists every table for which row level security is not switched on. That list should be empty before a project is shown to anyone.

Der geheime Schlüssel im Browser, in einem Notebook auf GitHub oder in einer settings.json bedeutet: Vollzugriff auf alle Daten für jeden, der ihn findet – ungeachtet aller Regeln. The secret key in the browser, in a notebook on GitHub or in a settings.json means: full access to all data for anyone who finds it – regardless of every rule. That is the one mistake in this lab that costs more than time. Hence the rule from labs 04 and 02 applies here unchanged: no secret in a file that gets passed on.

Zum Stand 09/2026 laufen die alte und die neue Benennung parallel; Supabase hat angekündigt, die Schlüssel anon und service_role bis Ende 2026 auslaufen zu lassen. Für neue Projekte also die neuen Bauformen verwenden – und in älteren Anleitungen die alten Namen als dasselbe lesen. As of 09/2026 the old and new naming run in parallel; Supabase has announced it will deprecate the anon and service_role keys by the end of 2026. So for new projects use the new forms – and in older guides read the old names as the same thing.

Verbinden – drei WegeConnecting – three routes

Der Knopf Connect zeigt drei Verbindungszeichenketten, und die Wahl ist keine Geschmacksfrage: In vielen Hochschulnetzen funktioniert genau eine davon. The Connect button shows three connection strings, and the choice is not a matter of taste: in many university networks exactly one of them works.

Die IPv6-FalleThe IPv6 trap

Die Direktverbindung db.[REF].supabase.co löst nur über IPv6 auf. In einem Netz ohne IPv6 – viele Hochschul-WLANs, viele VPN-Zugänge – scheitert sie mit einer Zeitüberschreitung, ohne dass die Meldung die Ursache nennt. Das kostet regelmäßig eine halbe Übungsstunde mit der falschen Vermutung, das Passwort sei falsch. The direct connection db.[REF].supabase.co resolves over IPv6 only. In a network without IPv6 – many university networks, many VPN accesses – it fails with a timeout without the message naming the cause. That regularly costs half a practical session with the wrong guess that the password is wrong.

Der Ausweg ist der Session Pooler auf Port 5432: Er ist über IPv4 erreichbar, in allen Plänen enthalten und für Werkzeuge wie DataGrip der richtige Weg. Zwei Fallen dabei: Der Benutzername enthält die Projektkennung (postgres.[REF], nicht postgres), und Port 6543 ist der Transaction Pooler – der eignet sich nicht für Datenbankwerkzeuge, weil er keinen Sitzungszustand hält. The way out is the session pooler on port 5432: it is reachable over IPv4, included in all plans, and the right route for tools such as DataGrip. Two traps here: the user name contains the project reference (postgres.[REF], not postgres), and port 6543 is the transaction pooler – unsuitable for database tools because it keeps no session state.

PausierenPausing

Projekte im kostenlosen Plan werden nach etwa einer Woche ohne Zugriff pausiert. Nichts ist verloren, aber die Datenbank antwortet nicht mehr, bis Sie sie im Dashboard wiederherstellen. Vor einem Übungstermin nach den Ferien also einmal aufwecken. Free-plan projects are paused after roughly a week without access. Nothing is lost, but the database stops answering until you restore it in the dashboard. So wake it up once before a session after a break.

VerbindungenConnections

Die kleinste Instanz erlaubt 60 direkte Verbindungen und 200 über den Pooler. Ein Datenbankwerkzeug öffnet oft mehrere gleichzeitig – dreißig Studierende auf demselben Projekt kommen der Grenze nahe. Ausweg: je Person ein eigenes Projekt, oder der Pooler. The smallest instance allows 60 direct connections and 200 through the pooler. A database tool often opens several at once – thirty students on the same project come close to the limit. Way out: one project per person, or the pooler.

SicherungBackup

Im kostenlosen Plan gibt es keine automatische Wiederherstellung auf einen Zeitpunkt. Eine eigene Sicherung ist ein Befehl: pg_dump gegen die Verbindungszeichenkette. Vor Semesterende einmal ausführen und die Datei aufbewahren. The free plan has no automatic point-in-time restore. Your own backup is one command: pg_dump against the connection string. Run it once before the end of the semester and keep the file.

Region ist nicht allesThe region is not everything

Supabase weist selbst darauf hin, dass die Regionswahl allein keine DSGVO-Konformität herstellt: Sicherungen, Protokolle, ausgeleitete Daten, die Ausführung von Edge Functions und Unterauftragnehmer können den Speicherort berühren. Für Übungen mit synthetischen Daten ist das ohne Belang – und genau deshalb wird es so gehandhabt. Supabase itself points out that the choice of region alone does not create GDPR compliance: backups, logs, exported data, edge function execution and sub-processors can affect where data resides. For exercises with synthetic data that is irrelevant – and that is exactly why it is handled that way.

Selbst-HostingSelf-hosting

Die Plattform ist quelloffen und läuft per Docker Compose auf eigener Infrastruktur – damit entfallen Grenzen, Pausieren und die Frage des Speicherorts vollständig. Der Preis: Betrieb, Aktualisierungen, Sicherungen und Überwachung liegen bei Ihnen. Bemerkenswert dabei: Selbst gehostetes Supabase ist selbst ein Compose-Stapel – Lab 07 und Lab 08 treffen sich hier. The platform is open source and runs on your own infrastructure via Docker Compose – which removes limits, pausing and the residency question entirely. The price: operation, updates, backups and monitoring are yours. Notably: self-hosted Supabase is itself a Compose stack – labs 07 and 08 meet here.

Die Verantwortung ist geteilt: Supabase sichert die Infrastruktur, für die Verarbeitung in Ihrer Anwendung, für Einwilligungen und für die Zugriffskontrolle sind Sie zuständig. Eine Hochschule, die den Dienst mit personenbezogenen Daten einsetzt, ist Verantwortliche und braucht einen Auftragsverarbeitungsvertrag. Für die Übungen dieses Kurses gilt die einfachere Regel: nur synthetische oder offene Daten – dann entfällt die Frage. Responsibility is shared: Supabase secures the infrastructure; the processing in your application, the consent flows and the access controls are yours. A university using the service with personal data is the controller and needs a data processing agreement. For this course's exercises the simpler rule applies: only synthetic or open data – then the question does not arise.
