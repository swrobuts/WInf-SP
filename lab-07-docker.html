Docker

„Bei mir läuft es“ ist der Satz, an dem Analytics-Projekte scheitern – nicht am Modell. Docker verpackt eine Anwendung samt Bibliotheken und Konfiguration in ein Image, das auf jedem Rechner mit Container-Laufzeit unverändert startet. Für diesen Kurs heißt das ganz praktisch: Eine PostgreSQL-Datenbank ist ein Befehl und eine Minute. Die eigentliche Lernfrage kommt danach – wovon überleben ihre Daten das Löschen des Containers? Wer das beantworten kann, hat Docker verstanden. “It works on my machine” is the sentence analytics projects fail on – not the model. Docker packs an application with its libraries and configuration into an image that starts unchanged on any machine with a container runtime. For this course that means, quite practically: a PostgreSQL database is one command and one minute. The actual learning question comes afterwards – what makes its data survive the container being deleted? Whoever can answer that has understood Docker.

Das Problem, das es löstThe problem it solves

Die Vorlesung nennt Deployment den Engpass von Analytics-Projekten: Ideen und Prototypen sind zahlreich, in Betrieb geht wenig. Eine der genannten Ursachen heißt „fehlende Skalierbarkeit und Portabilität, Komplexität im IT-Betrieb“. Genau dort setzt ein Container an. Er beantwortet die Frage nicht „welches Modell?“, sondern „wie kommt dieses Modell auf einen anderen Rechner, ohne dass ein Mensch drei Tage eine Umgebung einrichtet?“ The lecture calls deployment the bottleneck of analytics projects: ideas and prototypes are plentiful, little goes into operation. One of the named causes reads “lack of scalability and portability, complexity in IT operations”. That is exactly where a container applies. It answers not the question “which model?” but “how does this model get onto another machine without a human spending three days setting up an environment?”

Container ist keine virtuelle MaschineA container is not a virtual machine

Eine virtuelle Maschine bringt ein vollständiges Betriebssystem samt eigenem Kern mit – ein Gigabyte und eine Minute Startzeit. Ein Container teilt den Kern des Hosts und enthält nur die Anwendung samt ihrer Bibliotheken – ein Bruchteil davon und Startzeit in Sekunden. Der Preis: Die Trennung ist schwächer als bei einer virtuellen Maschine. Ein Container ist eine Verpackung, keine Festung – für die Übungen dieses Kurses ist das ohne Belang, für den Betrieb fremden Codes nicht. A virtual machine brings a complete operating system with its own kernel – a gigabyte and a minute of start-up time. A container shares the host's kernel and contains only the application with its libraries – a fraction of that and start-up in seconds. The price: the separation is weaker than with a virtual machine. A container is a packaging, not a fortress – irrelevant for this course's exercises, not irrelevant for running somebody else's code.

Image, Container, VolumeImage, container, volume

Drei Begriffe, und die ersten zwei werden am Anfang durchgängig verwechselt. Die Verwechslung ist die Ursache der beiden häufigsten Fehlermeldungen des Labs. Three concepts, and the first two get confused throughout at the beginning. That confusion is the cause of this lab's two most common error messages.

Aus einem Image entstehen beliebig viele Container. Ein Container hat ein eigenes, flüchtiges Dateisystem: Was er schreibt, ist mit ihm weg. Das ist Absicht und der Kern des Versprechens – ein Container startet immer im gleichen Zustand. Und es ist der Grund, warum eine Datenbank in einem Container ohne Volume ein Missverständnis ist. From one image, any number of containers arise. A container has its own, transient file system: what it writes is gone with it. That is by design and the core of the promise – a container always starts in the same state. And it is the reason why a database in a container without a volume is a misunderstanding.

Dasselbe Denkmodell wie in Lab 04: Die Laufzeit gehört Google und wird eingezogen, was überleben soll, geht nach Drive. Hier gehört das Container-Dateisystem Docker und wird gelöscht, was überleben soll, geht in ein Volume. Zwei Werkzeuge, dieselbe Unterscheidung zwischen flüchtigem und dauerhaftem Speicher. The same mental model as in lab 04: the runtime belongs to Google and gets taken back, what should survive goes to Drive. Here the container's file system belongs to Docker and gets deleted, what should survive goes into a volume. Two tools, the same distinction between transient and persistent storage.

Inbetriebnahme und LizenzSetting it up, and the licence

Für den Einstieg auf einem privaten Rechner ist Docker Desktop der bequemste Weg: Installer, grafische Oberfläche, Kommandozeile inbegriffen. Systemvoraussetzungen: Windows 10 (22H2) oder 11 mit mindestens 8 GB Arbeitsspeicher und aktivierter Virtualisierung im BIOS; macOS in einer der drei aktuellen Hauptversionen mit mindestens 4 GB. Unter Windows Home stehen nur Linux-Container zur Verfügung – für diesen Kurs genügt das vollständig. For getting started on a private machine, Docker Desktop is the most convenient route: installer, graphical interface, command line included. System requirements: Windows 10 (22H2) or 11 with at least 8 GB of memory and virtualisation enabled in the BIOS; macOS in one of the three current major versions with at least 4 GB. On Windows Home only Linux containers are available – entirely sufficient for this course.

Die Lizenzklausel, die man kennen mussThe licence clause you have to know

Docker Desktop ist kostenlos für persönliche und Bildungsnutzung, für nicht-kommerzielle Open-Source-Projekte und für Unternehmen mit weniger als 250 Beschäftigten und weniger als 10 Mio. US-Dollar Jahresumsatz – beide Bedingungen zusammen. Behörden („Government Entities“) sind ausdrücklich ausgenommen und brauchen ein kostenpflichtiges Abonnement. Ob eine staatliche Hochschule darunter fällt, ist eine Frage an das Justiziariat, nicht an eine Lernumgebung; für Studierende auf privaten Geräten greift die Bildungsnutzung. Docker Desktop is free for personal and educational use, for non-commercial open-source projects and for companies with fewer than 250 employees and less than 10 million US dollars in annual revenue – both conditions together. Government entities are expressly excluded and need a paid subscription. Whether a state university falls under that is a question for legal counsel, not for a learning environment; for students on private devices educational use applies.

Wer die Frage vermeiden will, hat drei Wege, die alle unter freien Lizenzen stehen: Docker Engine (Apache 2.0, Linux oder in einer WSL2-Distribution unter Windows – dieselbe Kommandozeile, keine grafische Oberfläche), Podman Desktop (Apache 2.0, ohne Hintergrunddienst, alias docker=podman funktioniert weitgehend) und Rancher Desktop (Apache 2.0, mit grafischer Oberfläche). Alles, was Sie hier lernen, gilt in allen dreien. Whoever wants to avoid the question has three routes, all under free licences: Docker Engine (Apache 2.0, Linux or in a WSL2 distribution on Windows – the same command line, no graphical interface), Podman Desktop (Apache 2.0, no background daemon, alias docker=podman works largely) and Rancher Desktop (Apache 2.0, with a graphical interface). Everything you learn here applies in all three.

Hinweis. Bei den in dieser Lernumgebung gezeigten Tools handelt es sich um eine Auswahl – diese ist weder als Empfehlung noch als Werbung zu verstehen. Docker steht hier, weil seine Begriffe zum Standard geworden sind und in Anleitungen vorausgesetzt werden; die Alternativen im Kasten darüber leisten dasselbe. Note. The tools shown in this learning environment are a selection – it is meant neither as a recommendation nor as advertising. Docker appears here because its vocabulary has become the standard and is assumed in guides; the alternatives in the box above do the same job.

Der erste ContainerThe first container

Nach docker run --rm hello-world zeigt docker ps nichts an, aber docker images zeigt ein Image. Genau daran hängt der Unterschied: Der Container ist gelaufen und weg, die Vorlage ist geblieben. Wer das nachvollzogen hat, versteht auch, warum docker rmi auf einen Container nicht wirkt und docker rm nicht auf ein Image. After docker run --rm hello-world, docker ps shows nothing, but docker images shows an image. The distinction hangs on exactly that: the container ran and is gone, the template stayed. Whoever has followed that also understands why docker rmi has no effect on a container and docker rm none on an image.

PortsPorts

Ein Container ist nach außen abgeschlossen. Damit ein Dienst darin erreichbar ist, muss ein Port des Hosts auf einen Port im Container abgebildet werden. Die Schreibweise ist -p HOST:CONTAINER – und die Reihenfolge zu verwechseln ist der zweithäufigste Fehler dieses Labs. A container is closed off to the outside. For a service inside it to be reachable, a port on the host has to be mapped to a port in the container. The notation is -p HOST:CONTAINER – and mixing up the order is this lab's second most common mistake.

Ein Host-Port lässt sich nur einmal vergeben. Läuft auf Ihrem Rechner schon ein PostgreSQL, ist 5432 besetzt, und docker run scheitert mit port is already allocated. Der Ausweg ist nicht, das andere zu beenden, sondern auszuweichen: -p 15432:5432. Der Container hört weiterhin auf 5432 – nur der Weg von außen führt über eine andere Tür. A host port can be assigned only once. If a PostgreSQL is already running on your machine, 5432 is taken, and docker run fails with port is already allocated. The way out is not to stop the other one but to move aside: -p 15432:5432. The container still listens on 5432 – only the route from outside goes through a different door.

Ein Detail mit Folgen: -p 5432:5432 bindet an alle Adressen des Rechners. Zusammen mit POSTGRES_PASSWORD=postgres ist die Datenbank damit im gesamten Hochschul-WLAN erreichbar. Für lokale Übungen gehört die Bindung an localhost: -p 127.0.0.1:5432:5432. Ein Zeichen mehr, ein Problem weniger. A detail with consequences: -p 5432:5432 binds to all of the machine's addresses. Together with POSTGRES_PASSWORD=postgres the database is thereby reachable across the whole university network. For local exercises the binding belongs on localhost: -p 127.0.0.1:5432:5432. One character more, one problem less.

Daten, die überlebenData that survives

Ein Volume (englisch volume) ist ein von Docker verwalteter Speicherbereich, der in den Container eingehängt wird und dessen Löschung überlebt. Ohne Volume ist eine Datenbank im Container ein Spielzeug; mit Volume ist sie eine Datenbank. A volume is a storage area managed by Docker, mounted into the container and surviving its deletion. Without a volume, a database in a container is a toy; with a volume it is a database.

Zwei Arten, etwas einzuhängenTwo ways of mounting something

  • Benanntes Volume – -v pgdata:/var/lib/postgresql/data. Docker verwaltet den Ort; Sie geben nur einen Namen. Für Datenbanken der richtige Weg: schnell, plattformunabhängig, und Sie können sich nicht versehentlich in einen falschen Ordner schreiben. Named volume – -v pgdata:/var/lib/postgresql/data. Docker manages the location; you only give a name. The right route for databases: fast, platform-independent, and you cannot accidentally write into the wrong folder.
  • Einhängen eines Ordners – -v "$(pwd)/daten:/app/daten". Ein Ordner Ihres Rechners erscheint im Container. Für Notebooks und Skripte der richtige Weg: Sie bearbeiten die Dateien im Editor, der Container sieht sie sofort. Erkennungsmerkmal: Vor dem Doppelpunkt steht ein Pfad, kein Name. Bind mount – -v "$(pwd)/daten:/app/daten". A folder on your machine appears in the container. The right route for notebooks and scripts: you edit the files in the editor, the container sees them immediately. Distinguishing feature: before the colon stands a path, not a name.

Ein eigenes ImageYour own image

Bis hierhin haben Sie fremde Images benutzt. Ein eigenes entsteht aus einer Textdatei namens Dockerfile – und ist der Punkt, an dem aus „bei mir läuft es“ ein reproduzierbares Ergebnis wird: Die Datei sagt vollständig und nachlesbar, aus welchem Base Image, mit welchen Paketen und mit welchem Startbefehl die Auswertung läuft. Up to here you have used other people's images. Your own arises from a text file called Dockerfile – and is the point where “it works on my machine” becomes a reproducible result: the file says completely and readably from which base image, with which packages and with which start command the analysis runs.

Die Reihenfolge im Dockerfile ist keine Geschmacksfrage. Docker baut in Schichten und verwendet unveränderte Schichten wieder. Steht COPY . . vor RUN pip install, wird bei jeder Codeänderung neu installiert – zwei Minuten je Bau. Steht die Paketliste zuerst und der Code danach, dauert derselbe Bau zwei Sekunden. Selten Geändertes nach vorn, häufig Geändertes nach hinten. The order in the Dockerfile is not a matter of taste. Docker builds in layers and reuses unchanged layers. If COPY . . comes before RUN pip install, every code change reinstalls everything – two minutes per build. With the package list first and the code afterwards, the same build takes two seconds. Rarely changed things to the front, frequently changed things to the back.

Mehrere Container: ComposeSeveral containers: Compose

Eine Datenbank allein hilft wenig – man will auch ein Werkzeug, das sie abfragt. Zwei docker run-Zeilen mit sechs Optionen jedes Mal von Hand zu tippen ist fehleranfällig; genau dafür gibt es compose.yaml. Die Datei beschreibt den gewünschten Zustand, und ein Befehl stellt ihn her. A database alone helps little – you also want a tool to query it. Typing two docker run lines with six options each by hand every time is error-prone; that is exactly what compose.yaml is for. The file describes the desired state, and one command produces it.

Der gefährlichste Befehl dieses Labs ist docker compose down -v. Ohne -v werden Container und Netz entfernt, die Volumes bleiben – die Datenbank ist beim nächsten up wieder da. Mit -v gehen die Volumes mit, und die Datenbank ist leer. Der Unterschied sind zwei Zeichen, und er ist der häufigste Datenverlust im Kurs. In der Konsole auf dieser Seite können Sie ihn gefahrlos herbeiführen; die Umgebung sagt Ihnen dann, was passiert ist. The most dangerous command in this lab is docker compose down -v. Without -v, containers and network are removed and the volumes stay – the database is back at the next up. With -v the volumes go too, and the database is empty. The difference is two characters, and it is the most common data loss in the course. In the console on this page you can bring it about safely; the environment then tells you what happened.

AufräumenTidying up

Images, Bau-Zwischenstände, gestoppte Container und verwaiste Volumes summieren sich. Zwanzig bis fünfzig Gigabyte nach einem Semester sind normal, und die Meldung, die dann kommt, lautet nicht „Docker ist voll“, sondern „no space left on device“ – irgendwo anders auf dem Rechner. Images, build caches, stopped containers and orphaned volumes add up. Twenty to fifty gigabytes after a semester is normal, and the message that then appears is not “Docker is full” but “no space left on device” – somewhere else on the machine.

StolpersteineStumbling blocks

latest

latest ist kein „neuestes“, sondern ein Name, den der Herausgeber beliebig verschiebt. Ein Notebook, das heute mit postgres:latest läuft, kann im nächsten Semester auf einer anderen Hauptversion landen. Immer ausdrücklich taggen: postgres:16.4. Dasselbe Prinzip wie das Festnageln der Paketversionen in Lab 04. latest is not “newest” but a name the publisher moves at will. A notebook running on postgres:latest today can land on a different major version next semester. Always tag explicitly: postgres:16.4. The same principle as pinning package versions in lab 04.

arm64 · amd64

Auf Apple Silicon läuft ein Image, das nur für amd64 gebaut ist, entweder emuliert und langsam oder gar nicht – dann meldet sich exec format error. Abhilfe: Mehr-Architektur-Images bevorzugen, sonst --platform linux/amd64 ausdrücklich setzen und die Geschwindigkeitseinbuße einkalkulieren. On Apple Silicon an image built only for amd64 either runs emulated and slowly or not at all – then exec format error appears. Remedy: prefer multi-architecture images, otherwise set --platform linux/amd64 explicitly and factor in the loss of speed.

Geheimnisse im ImageSecrets in the image

COPY .env . oder ENV PASSWORD=… schreibt das Geheimnis in eine Schicht – und Schichten bleiben lesbar, auch wenn eine späte Zeile die Datei löscht. Zu prüfen mit docker history. Zugangsdaten gehören zur Laufzeit hinein: -e, --env-file oder secrets in Compose. Dieselbe Regel wie in Lab 04 und Lab 02, nur ein anderes Werkzeug. COPY .env . or ENV PASSWORD=… writes the secret into a layer – and layers stay readable even if a later line deletes the file. Check with docker history. Credentials belong in at runtime: -e, --env-file or secrets in Compose. The same rule as in labs 04 and 02, just a different tool.

429

Unangemeldet erlaubt Docker Hub 100 Abrufe je sechs Stunden – gezählt je IP-Adresse. Ein Seminarraum teilt sich diese 100 und erhält nach wenigen Minuten 429 Too Many Requests. Abhilfe: docker login mit persönlichem Konto (200 je sechs Stunden je Person), Images vor der Veranstaltung ziehen, oder einen lokalen Spiegel betreiben. Anonymously Docker Hub allows 100 pulls per six hours – counted per IP address. A seminar room shares those 100 and gets 429 Too Many Requests after a few minutes. Remedy: docker login with a personal account (200 per six hours per person), pull the images before class, or run a local mirror.

Container startet und endetContainer starts and ends

Ein Container lebt, solange sein Hauptprozess lebt. Endet der Startbefehl, endet der Container – das ist kein Fehler, sondern die Definition. docker logs <name> sagt, warum: meist eine fehlende Environment Variable oder ein Tippfehler im Befehl. A container lives as long as its main process lives. When the start command ends, the container ends – that is not an error but the definition. docker logs <name> says why: usually a missing environment variable or a typo in the command.

Fremde ImagesOther people's images

Ein beliebiges Image aus dem Hub führt fremden Code aus, im Container mit Verwaltungsrechten. Auf Docker Official Image und Verified Publisher achten. --privileged und das Einhängen des Docker-Sockets heben die Trennung praktisch auf – in einer Anleitung, die das verlangt, sollte man zweimal lesen, wofür. Any image from the Hub runs somebody else's code, inside the container with administrative rights. Look for Docker Official Image and Verified Publisher. --privileged and mounting the Docker socket practically remove the separation – in a guide that demands this, it is worth reading twice what for.
